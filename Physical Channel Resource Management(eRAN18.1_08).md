4 PHICH Resource Management
## 4.1 Principles
The PHICH carries hybrid automatic repeat request (HARQ) ACK and NACK for
uplink data.
The eNodeB performs PHICH resource management by default and allocates
PHICH resources according to 3GPP specifications. The PHICH resource positions
for each UE in the uplink are determined by the PUSCH information, PHICH
duration, and the number of PHICH groups of this UE. For details, see section 6.9
"Physical hybrid ARQ indicator channel" in 3GPP TS 36.211 V10.4.0.
●  The PHICHCfg.
PhichDuration parameter specifies the type of PHICH duration
as follows:
In general cases, when macro eNodeBs are deployed in urban areas, the
coverage of each channel is able to meet basic requirements. Therefore, it is
recommended that the PHICHCfg.
PhichDuration parameter be set to
NORMAL in this scenario. In the case of vast coverage (for example, over
desert or ocean areas) or when coverage expansion is needed for micro
eNodeBs falling victim to severe interference from adjacent macro eNodeBs, it
is recommended that this parameter be set to EXTENDED to achieve better
demodulation performance.
–   If this parameter is set to NORMAL, the PHICH is mapped only to the
first orthogonal frequency division multiplexing (OFDM) symbol of a
subframe, and the number of OFDM symbols occupied by a PDCCH is
adaptively adjusted.
–   If this parameter is set to EXTENDED, the PHICH is mapped to the first
three OFDM symbols and the three resource element groups (REGs) are
allocated on the three symbols to obtain time diversity gains. Therefore,
demodulation performance at the physical layer in some scenarios
outperforms that when this parameter is set to NORMAL. When this
parameter is set to EXTENDED, PDCCH symbol adaptation does not take
effect and a PDCCH occupies a fixed number of OFDM symbols. The
number of OFDM symbols occupied by a PDCCH depends on the
bandwidth.

four UEs.

maximum, the number of UEs using CDM in each PHICH group is the
minimum, and the PHICH demodulation performance is the best.
However, the number of resources occupied by the PHICH increases, and
the number of scheduling indications sent on the PDCCH decreases.

The PHICH duration and the number of PHICH groups affect the downlink
capacity. A longer PHICH duration or a larger number of PHICH groups leads to
higher PHICH resource consumption, fewer available PDCCH resources, and

demodulation performance and probably more uplink data transmission failures.

5 PDCCH/ePDCCH Resource Management
## (FDD)
5.1 PDCCH/ePDCCH Information Types
The PDCCH/ePDCCH transmits the following three types of downlink control
information (DCI):
●  Downlink grant
This DCI includes the PDSCH resource indicator, modulation and coding
scheme (MCS), HARQ process number, and PUCCH power control commands.
The format can be format 1, 1A, 1B, 1C, 1D, 2, 2A, 2B, 2C, or 2D.
●  Uplink grant
This DCI includes the PUSCH resource indicator, MCS, and PUSCH or PUCCH
power control commands. The format can be format 0 or format 4.
●  Power control commands
This DCI is a group of PUSCH power control commands for a UE, which
supplement PUSCH/PUCCH power control commands in an uplink grant. The
format can be format 3 or 3A.

## 5.2.1 Principles
PDCCH symbol adaptation enables the eNodeB to adjust the number of symbols
occupied by a PDCCH based on the number of required CCEs.
●  When a PDCCH requires fewer CCEs, the eNodeB decreases the number of
symbols occupied by the PDCCH and allocates idle time-frequency resources
to PDSCHs.
●  When a PDCCH requires more CCEs, the eNodeB increases the number of
symbols occupied by the PDCCH until the number reaches the maximum
permissible value.
To rapidly provide CCEs as required and prevent ping-pong adjustments to the
number of symbols occupied by a PDCCH, the eNodeB can rapidly increase and
slowly decrease the number of symbols occupied by the PDCCH.
Figure 5-3 shows the procedure for PDCCH symbol adaptation.
Figure 5-3 Procedure for PDCCH symbol adaptation
The CellPdcchAlgo.PdcchSymNumSwitch parameter specifies whether to enable
PDCCH symbol adaptation.
●  When the CellPdcchAlgo.
PdcchSymNumSwitch parameter is set to ON,
PDCCH symbol adaptation is enabled, and CCE usage must be measured to

check whether CCEs are sufficient. The measurement method of CCE
resources is as follows:
–   If uplink or downlink CCEs for scheduling fail to be allocated within the
previous transmission time interval (TTI), CCEs are insufficient. In this
situation, the number of symbols occupied by the PDCCH needs to be
increased. Uplink scheduling CCEs transmit uplink grants, and downlink
scheduling CCEs transmit downlink scheduling allocations.
–   If no CCE allocation failure occurs within a certain period of time and the
remaining CCEs are sufficient, the number of required CCEs is less than
the number of available CCEs in the symbols. In this situation, the
number of symbols occupied by the PDCCH needs to be decreased.
●  When the CellPdcchAlgo.

function enables symbol adaptation to be based on downlink load, CCE load,
and scheduling type. Compared with the case where this parameter is set to
ON, ECfiAdaptionON enables the number of symbols occupied by the PDCCH
to be increased in a slower manner and be decreased in a quicker manner.
–   When the downlink load is greater than 90%, the number of symbols will
not be increased in case CCE allocation fails for downlink scheduling.
–   When the downlink load is greater than 90%, as long as CCE allocation
failure for uplink scheduling does not occur during the previous TTI and
the remaining CCE resources are sufficient, the eNodeB immediately
decreases the number of symbols occupied by the PDCCH.
–   When the remaining CCE resources are sufficient, the number of symbols
will not be increased in the case of CCE allocation failures. The threshold
for determining whether remaining CCE resources are sufficient is
specified by the CellPdcchAlgo.

–   When the CellPdcchAlgo.HysForCfiBasedPreSch parameter is set to 0 or
the CellPdcchAlgo.

occupied by the PUCCH. Therefore, adjusting the

recommended. If the parameter value is changed, conflicts between the
PUCCH and other channels may occur, which leads to performance loss.

## 5.2.2.1 Benefits
This section analyzes the benefits of PDCCH symbol adaptation, PDCCH
aggregation level adaptation, and closed-loop adjustment to the PDCCH
aggregation level.
The application scenarios of the preceding functions are described as follows:
●  PDCCH symbol adaptation is enabled by default. In ultra-high-speed
scenarios, you are advised to disable this function. In non-ultra-high-speed
scenarios, you are advised to enable this function. Enhanced PDCCH symbol
adaptation is recommended if frequency selective scheduling is enabled. For
details about frequency selective scheduling, see
## Scheduling.
●  PDCCH aggregation level adaptation is enabled by default. No manual
operation is required for parameter setting.
●  Closed-loop adjustment to the PDCCH aggregation level is enabled by default.
It is recommended that this function be used.
PDCCH symbol adaptation enables the eNodeB to allocate PDCCH symbols
reasonably and therefore achieves optimum uplink and downlink performance.
PDCCH aggregation level adaptation and closed-loop adjustment ensure the
PDCCH demodulation performance and therefore increase the cell throughput and
enhance the edge coverage.
On basis of dynamic adjustment, enabling enhanced PDCCH symbol adaptation,
setting the hysteresis of CFI number increase caused by uplink preallocation
failures to 0, and setting the CCE threshold for CFI adjustment to a smaller value,

5.3 PDCCH Aggregation Level Adaptation
## 5.3.1 Principles
A CCE is the smallest resource unit for transmission on a PDCCH. Each CCE
contains nine REGs and carries 72-bit information. Each REG contains four
resource elements (REs). Based on code rates, the eNodeB can aggregate one,
two, four, or eight CCEs to constitute a PDCCH, which corresponds to aggregation
level 1, 2, 4, or 8, as stipulated in 3GPP specifications. The aggregation level
indicates the number of CCEs a PDCCH occupies. For example, if the aggregation
level is 1, the PDCCH occupies one CCE; if the aggregation level is 2, the PDCCH
occupies two CCEs.
●  PDCCHs with aggregation level 8 have the lowest code rate and the best
demodulation performance.
If PDCCH aggregation levels for all UEs in a cell are set to 8, CCE resources for
PDCCHs are wasted for UEs in the cell center and at a medium distance from
the cell center.
●  PDCCHs with aggregation level 1 have the highest code rate and the worst
demodulation performance.
If PDCCH aggregation levels for all UEs in a cell are set to 1, PDCCHs may not
be correctly demodulated by UEs at a medium distance from the cell center
and at the cell edge.
This function enables the eNodeB to select an appropriate PDCCH aggregation
level based on channel quality, which helps maximize the demodulation
performance and capacity of the PDCCH.
●  Channel quality is derived from the channel quality indicator (CQI).
●  An appropriate PDCCH aggregation level is the lowest aggregation level
ensuring that BLERs are less than 1.5%.
The eNodeB provides the aggregation level adaptation function for PDCCHs
carrying uplink and downlink grants. Under satisfactory PDCCH demodulation
performance conditions, PDCCH aggregation level adaptation can minimize
resources occupied by the PDCCH, reduce PDCCH load, reduce interference to
neighboring cells, and improve system performance.
This function enables the eNodeB to select an appropriate PDCCH aggregation
level based on the signal to interference plus noise ratio (SINR), which is
calculated based on the MCS index for the scheduled PDSCH. Figure 5-4 shows
the procedure.

5.4 Closed-Loop Adjustment to the PDCCH Aggregation
## Level
## 5.4.1 Principles
The PDCCH aggregation level may be inaccurate on the live network due to the
following causes. In severe cases, service drops may occur.
●  The interference with the PDSCH differs from the interference with the
## PDCCH.
●  Periodic CQI adjustment used for selecting an MCS is slower than channel
condition changes.
Therefore, closed-loop adjustment to the PDCCH aggregation level is added, which
is used to dynamically adjust the PDCCH aggregation level based on the PDCCH
## BLER.
●  If the PDCCH BLER is greater than the target BLER, the closed-loop
adjustment raises the aggregation level to improve the PDCCH coverage
performance.
●  If the PDCCH BLER is less than the target BLER, the closed-loop adjustment
lowers the aggregation level to reduce the PDCCH resource consumption.
The CellPdcchAlgo.
PdcchAggLvlCLAdjustSwitch parameter specifies whether to
enable closed-loop adjustment to the PDCCH aggregation level.
The PDCCH BLER is calculated based on the downlink DCI or uplink DCI 0. Closed-
loop adjustment to the PDCCH aggregation level in the downlink is based on the
downlink DCI. The PuschDtxSwitch option of the CellAlgoSwitch.
UlSchSwitch
parameter determines whether closed-loop adjustment to the PDCCH aggregation
level in the uplink is based on the downlink DCI or uplink DCI 0 as follows:
●  Uplink DCI 0 if the option is selected.
●  All downlink DCIs if the option is deselected.
The CellPdcchAlgo.
PdcchBlerTarget parameter indicates the target BLER of the
closed-loop adjustment to the PDCCH aggregation level. A larger or smaller value
of this parameter may result in negative throughput gains. The default value is
recommended.
●  A larger value of this parameter increases PDCCH capacity but increases the
DTX proportion of the PDCCH and reduces the system throughput.
●  A smaller value of this parameter decreases the DTX proportion of the
PDCCH, results in a high PDCCH aggregation level, reduces the system
capacity, and reduces the system throughput when CCE resources are
insufficient.
The CellPdcchAlgo.
PdcchOutLoopAdjBaseStep parameter specifies the baseline
step used for outer-loop adjustment to the PDCCH. The selection of an
appropriate step for the adjustment is dependent on this baseline step and
channel quality.

●  A smaller value of this parameter decelerates DTX-based outer-loop
adjustment to the PDCCH. As a result, the aggregation level adjustment is
slower and cannot effectively adapt to channel quality upon drastic channel

●  A larger value of this parameter accelerates DTX-based outer-loop adjustment

scenarios, for example, PDSCH quality is better than PDCCH quality.

outer-loop adjustment to the PDCCH and therefore looser restriction on
aggregation level adjustment. This ensures normal DTX-based PDCCH
aggregation level adjustment in special scenarios, for example, PDSCH quality
is better than PDCCH quality.
In the case of severe uplink interference, the DTX probability incurred by
uplink transmissions is high. In this situation, setting this parameter to a
smaller value results in excessive aggregation level adjustment, causing the
capacity to decrease.
## 5.4.2 Network Analysis
## 5.4.2.1 Benefits
For details about the benefits of closed-loop adjustment to the PDCCH
aggregation level, see 5.2.2.1 Benefits.
The step and range for closed-loop adjustment to the PDCCH aggregation level
affect the accuracy of aggregation level selection. More accurate aggregation level
selection indicates more optimum selection of PDCCH reliability and capacity.
More accurate PDCCH aggregation level selection affects the capacity as follows:
●  When the PDCCH BER is higher, the eNodeB promptly selects a higher PDCCH
aggregation level, leading to fewer spectrum resource wastes but lowered
system capacity.
●  When the PDCCH BER is lower, the eNodeB can select a lower PDCCH
aggregation level in time. Fewer CCE resources are required, increasing system
capacity. However, the BER will increase in this case.
The CellPdcchAlgo.
PdcchOutLoopAdjBaseStep and
CellPdcchAlgo.PdcchOutLoopAdjLowerLimit parameters specify the baseline
step and adjustment range used for closed-loop adjustment to the PDCCH
aggregation level, allowing for quicker and more accurate aggregation level
adjustment.
●  If the PDCCH BER is less than the target BER, the aggregation level decrease
can be accelerated to save CCE resources. This enables the PDCCH BER to
approximate to the preset target value. However, the DTX times will slightly
increase. In heavy-load scenarios, the data rates of UEs and cells increase.

5.5 CCE Ratio Adaptation
## 5.5.1 Principles
Uplink CCEs transmit uplink grants, and downlink CCEs transmit downlink grants.
The CCE ratio is a ratio of the number of uplink CCEs to the number of downlink
CCEs.
To adapt to changes in uplink and downlink services and improve cell throughput
and quality of service (QoS), the eNodeB dynamically adjusts the CCE ratio based
on the usage of uplink and downlink CCEs.
The CellPdcchAlgo.
CceRatioAdjSwitch parameter specifies whether to enable
CCE ratio adaptation.
●  If the CellPdcchAlgo.
CceRatioAdjSwitch parameter is set to ON, the eNodeB
dynamically adjusts the CCE ratio in each TTI based on the usage of uplink
and downlink CCEs.
●  If the CellPdcchAlgo.
CceRatioAdjSwitch parameter is set to OFF, the
eNodeB does not dynamically adjust the CCE ratio. The CCE ratio is always 2:3
in a 5-MHz cell and is always 1:2 in a cell with a bandwidth other than 5
MHz.
The ReserveCommonCCESwitch option of the
CellPdcchAlgo.
UlPdcchAllocImproveSwitch parameter specifies whether to
reserve CCE resources in the common search space for the uplink.
●  When this option is selected, CCE resources in the common search space will
be reserved for the uplink. When PDCCH resources are insufficient, the uplink
CCE allocation success rate increases, and therefore the VoLTE capacity and
the access success rate increase. However, when the number of required
downlink CCE resources increases, the downlink scheduling delay for some
UEs increases.

●  When this option is deselected, CCE resources in the common search space
will not be reserved for the uplink. When PDCCH resources are insufficient,
the uplink CCE allocation success rate decreases and downlink scheduling
delay performance improves. However, this affects the VoLTE capacity and
access success rate.

5.6 ePDCCH Resource Management
## 5.6.1 Principles
An eCCE is the minimum resource unit for ePDCCH transmission. Based on code
rates, the eNodeB can aggregate 1, 2, 4, 8, 16, or 32 eCCEs to constitute an
ePDCCH, which corresponds to aggregation level 1, 2, 4, 8, 16, or 32, as stipulated
in 3GPP specifications. The aggregation level indicates the number of eCCEs
occupied by an ePDCCH. For example, if the aggregation level is 1, the ePDCCH
occupies one eCCE; if the aggregation level is 2, the ePDCCH occupies two eCCEs.
●  ePDCCHs with aggregation level 32 have the lowest code rate and best
demodulation performance.
If ePDCCH aggregation levels for all UEs in a cell are set to 32, eCCE resources
for ePDCCHs are wasted for UEs in the cell center.
●  ePDCCHs with aggregation level 1 have the highest code rate and worst
demodulation performance.
If ePDCCH aggregation levels for all UEs in a cell are set to 1, ePDCCHs may
not be correctly demodulated by UEs in the cell center and at the cell edge.
When the EpdcchFunctionSwitch option of the
CellPdcchAlgo.
EpdcchAlgoSwitch parameter is selected, ePDCCH is enabled and
ePDCCH resource management uses the following PDCCH switches:
CellPdcchAlgo.
PdcchAggLvlCLAdjustSwitch, CellPdcchAlgo.CceRatioAdjSwitch,
CellPdcchAlgo.
PdcchCapacityImproveSwitch,
CellPdcchAlgo.PdcchPowerEnhancedSwitch, and
CellPdcchAlgo.PdcchBlerTarget. For example, if ePDCCH and closed-loop
adjustment to the PDCCH aggregation level are enabled, ePDCCH uses the
mechanism of closed-loop adjustment to the PDCCH aggregation level. If ePDCCH
is enabled and closed-loop adjustment to the PDCCH aggregation level is disabled,
ePDCCH does not use the mechanism of closed-loop adjustment to the PDCCH
aggregation level. If UEs are using ePDCCH resources, these UEs continue using
ePDCCH resources until they exit even though ePDCCH is disabled.
This function has the following constraints:
●  ePDCCH does not support 5 MHz, 3 MHz, or 1.4 MHz narrow bandwidth,
non-standard bandwidth, or super combined cell scenarios.
●  ePDCCH supports 1-, 2-, and 4-antenna configurations and does not support
the 8-antenna configuration.
●  ePDCCH cannot be deployed on the LBBPc board.
●  ePDCCH resources can be used only when the PUCCHCfg.
DeltaShift
parameter is set to DS1_DELTA_SHIFT.

5.7 PDCCH Spare Power Allocation Optimization
## 5.7.1 Principles
When PDCCH power resources are not used up, this function can allocate PDCCH
spare power to UEs in areas with weak coverage or specified UEs with downlink-
large-packet reception, thereby fully utilizing PDCCH resources and improving
PDCCH reliability. When the number of downlink RBs used by a UE exceeds 70%
of the total number of RBs in a cell, the UE is receiving downlink large packets.
This function takes effect when the UsPdcchOptSwitch option of the
CellUSParaCfg.
UsAlgoSwitch parameter is deselected.
The CellPdcchAlgo.PdcchSparePowerAllocStrage parameter specifies the PDCCH
spare power allocation strategy.
●  When this parameter is set to NONE, this function does not allocate PDCCH
spare power.
●  When this parameter is set to WEAKCOVERAGEUSER, this function allocates
the spare power of the PDCCH of the current control format indicator (CFI) to
UEs in areas with weak coverage.
●  When this parameter is set to BIGPKTUSER, this function allocates the spare
power of the PDCCH of the current CFI to UEs with downlink-large-packet
reception.
## NO TE
When the CellPdcchAlgo.PdcchSparePowerAllocStrage parameter is set to
WEAKCOVERAGEUSER or BIGPKTUSER, the upper limit of the power increased for each
CCE cannot exceed 2 dB for UEs allocated additional power.

5.9 PDCCH Utilization Improvement
## 5.9.1 Principles
The CellPdcchAlgo.PdcchCapacityImproveSwitch parameter is used to improve
the PDCCH allocation success rate and PDCCH capacity.
●  If this parameter is set to ON and the CCE allocation for a UE fails, the
eNodeB increases the PDCCH power and lowers the PDCCH aggregation level
for the UE for CCE reallocation.
●  If this parameter is set to OFF and the CCE allocation for a UE fails, the
eNodeB does not increase the PDCCH power or lower the PDCCH aggregation
level for the UE for CCE reallocation.
The CellPdcchAlgo.
PdcchInitialCceAdjustValue parameter specifies the
adjustment value of the PDCCH initial aggregation level. A larger value of this
parameter indicates a smaller SRB initial aggregation level, less CCE resources
occupied by the PDCCH, and slightly worse PDCCH demodulation performance. A
smaller value of this parameter indicates a greater SRB initial aggregation level,
better PDCCH demodulation performance, and more occupied CCEs. In heavily
loaded networks, you are advised to set this parameter to 0, thereby decreasing
the SRB CCE consumption and increasing the number of UEs that access the cell.
The relationships between this parameter and
CellPdcchAlgo.
PdcchCapacityImproveSwitch and the setting requirements are as
follows:
●  If the CellPdcchAlgo.
PdcchCapacityImproveSwitch parameter is set to ON,
the adjustment values of the PDCCH initial aggregation level for SRBs and
DRBs depend on the value of the CellPdcchAlgo.
PdcchInitialCceAdjustValue
parameter. If the value of the CellPdcchAlgo.PdcchInitialCceAdjustValue
parameter is less than or equal to 0, the adjustment value of the PDCCH
initial aggregation level for SRBs is equal to the value of this parameter and
the adjustment value of the PDCCH initial aggregation level for DRBs is 0. If
the value of the CellPdcchAlgo.
PdcchInitialCceAdjustValue parameter is
greater than 0, the adjustment values of the PDCCH initial aggregation level
for SRBs and DRBs are equal to the value of this parameter.
●  If the CellPdcchAlgo.
PdcchCapacityImproveSwitch parameter is set to OFF,
the adjustment values of the PDCCH initial aggregation level for SRBs and
DRBs are equal to the value of the
CellPdcchAlgo.
PdcchInitialCceAdjustValue parameter.
The eNodeB can select a more accurate aggregation level based on the PDCCH
quality and proper PDCCH power, thereby decreasing the failure rate of allocating
the PDCCH aggregation level for PDCCH capacity improvement. The
CellPdcchAlgo.
PdcchPowerEnhancedSwitch parameter specifies whether to
enable PDCCH power control improvement.
●  If the CellPdcchAlgo.
PdcchPowerEnhancedSwitch parameter is not set to
OFF, the eNodeB selects a lower aggregation level based on the channel
quality. A lower aggregation level indicates a higher code rate and poorer

demodulation performance. To ensure PDCCH demodulation performance of

the cell.
●  For a cell with low average RB usage and sufficient CCE resources
The cell is lightly loaded in this case. This function does not increase the cell
throughput in this scenario. As most services on the live network are burst
services, this function reduces the number of symbols occupied by the PDCCH
in most cases. As a result, the downlink user-perceived rate can be increased.
The uplink user-perceived rate, on the other hand, does not change.
●  For a cell with RBs exhausted (RB usage greater than 95%) and sufficient CCE
resources

●  For a cell with RBs exhausted (RB usage greater than 95%) and high CCE

## PMI
A PMI indicates a precoding matrix. When closed-loop MIMO is enabled, the PMI

data and no interference will occur. For details, see
## MIMO.

## 6.1.2.2 Impacts
## Network Impacts
The PUCCH HARQ-ACK configuration has impacts on the downlink user-perceived
rate of CA UEs and the uplink system capacity.
●  If the SCCAckResourceCfgSw option of the
CellAlgoSwitch.
PucchAlgoSwitch parameter is deselected, a lower failure
rate threshold of code channel allocation and a lower threshold of code
channel usage result in a higher downlink user-perceived rate of CA UEs but
lead to a higher PUCCH resource overhead and accordingly a lower uplink
system capacity.
●  If the SCCAckResourceCfgSw option of the
CellAlgoSwitch.
PucchAlgoSwitch parameter is selected, a larger number of
2CC SCC ACK code channels and a larger number of RBs in format 3 result in
a higher downlink user-perceived rate of CA UEs but lead to a higher PUCCH
resource overhead and accordingly a lower uplink system capacity.
The period for sending CQIs on the PUCCH has impacts on the downlink user-
perceived rate and uplink system capacity. A shorter CQI reporting period results in
a higher downlink user-perceived rate and better user experience delivered by
downlink AMC but leads to a higher PUCCH resource overhead and accordingly a
lower uplink system capacity.
If the SRI reporting period is set to a fixed value:
●  A shorter SRI reporting period for UEs in the cell results in a lower SRI
capacity. However, it shortens the time for UEs to wait for uplink scheduling,
reducing the average uplink scheduling delay and improving user experience.

6.4 PUCCH Resource Allocation Policy
## 6.4.1 Principles
PUCCHCfg.PucchAllocPolicy specifies the PUCCH resource allocation policy.
The RbPriorityModeSW option of the PUCCHCfg.PucchAllocPolicy parameter
specifies whether resources on different RBs are used by preference during code
channel resource allocation.
●  When the RbPriorityModeSW option is selected, the eNodeB preferentially
uses resources on different RBs and evenly distributes UEs on all RBs during
PUCCH code channel resource allocation. This decreases inter-code
interference on most UEs in a cell and improves PUCCH detection
performance.
●  When the RbPriorityModeSW option is deselected, the eNodeB uses each RB
resource of the PUCCH wholly in sequence. UEs in the cell are mostly
distributed on RBs of the corresponding PUCCH format at the band edges.
Therefore, UEs on the RBs have greater inter-code-channel interference.
It is recommended that the RbPriorityModeSW option be selected for key event
assurance. When the PucchSwitch option of the

6.5 Flexible PUCCH Configuration
## 6.5.1 Principles
When the PUCCH experiences severe interference caused by inter-RAT signal
leakage, the access performance deteriorates and the downlink throughput
decreases. Flexible PUCCH configuration reduces or even prevents this interference
and therefore improves the access performance and increases the downlink
throughput. In addition, the frequency band originally reserved for the PUCCH can
be used to schedule uplink data to reduce the decrease in the PUSCH throughput.

is allocated from RB 0 and RB 99.

## 6.5.2 Network Analysis
## 6.5.2.1 Benefits
Flexible PUCCH configuration is disabled by default. This function is recommended
when both edges of the uplink band are experiencing strong interference (for
example, 20 dB higher interference to the PUCCH RBs than usual). Flexible PUCCH
configuration reduces the interference to the PUCCH. The CQIs (indicating
downlink channel quality) and RIs measured by UEs can be therefore reported to
eNodeBs in a timely manner, improving downlink performance. In other scenarios,
disabling flexible PUCCH configuration is recommended. Flexible PUCCH
configuration improves the PUCCH coverage and ensures the uplink and downlink
network performance when both edges of the uplink band are experiencing strong
interference. However, since RBs are not allocated from the band edges in flexible
PUCCH configuration, the PUSCH resources will be discontinuous, which may
lower the uplink resource usage.

7 SRS Resource Management (FDD)
## 7.1 Principles
In the LTE system, UEs periodically send SRSs across the entire PUSCH frequency
band as much as possible. After receiving the SRSs, the eNodeB processes them
and measures SINRs and time synchronization values on subcarriers in the PUSCH
frequency band for each UE.
●  SINRs are used for frequency selective scheduling of uplink channels, link
adaptation, and power control.
●  Time synchronization values are used for uplink time synchronization of UEs.
The SRSCfg.
SrsCfgInd parameter specifies whether to configure SRS resources for
UEs in a cell.
●  If this parameter is set to BOOLEAN_TRUE, SRS resources are available in the
cell and can be configured for UEs in the cell. Using SRS resources, instead of
PUSCH demodulation reference signals (DMRSs), reduces the PDCCH
consumption of PUSCH scheduling and therefore increase the downlink
capacity. To use open-loop and closed-loop MIMO adaptation or uplink virtual
MIMO (VMIMO), it is recommended that SRS resources be configured.
●  If this parameter is set to BOOLEAN_FALSE, no SRS resource is available in
the cell, and therefore no UE in the cell is configured with SRS resources. As
there is no SRS consumption, the uplink capacity increases. However, SRS-
dependent features such as frequency selective scheduling and VMIMO
cannot achieve better performance.
When an LBBPc board supports less than four receive antennas, the
SRSCfg.
SrsCfgInd parameter can be set to BOOLEAN_TRUE or BOOLEAN_FALSE.
When this parameter is set to BOOLEAN_FALSE, VMIMO is not supported. When
the LBBPc board supports four or more receive antennas or the extended CP
function is enabled, the SRSCfg.
SrsCfgInd parameter can be set only to
BOOLEAN_TRUE. If an LBBPd board is used, this parameter can be set to either
BOOLEAN_TRUE or BOOLEAN_FALSE.
The SRSCfg.
FddSrsCfgMode parameter must be set to specify the SRS resource
allocation mode for macro LTE FDD cells when the SRSCfg.
SrsCfgInd parameter is

7.1.3.2 UE-specific SRS Period Adaptation
The eNodeB can adaptively adjust the SRS period for individual UEs based on SRS
loads. This way is called UE-specific SRS period adaptation.
The settings of the parameters CellSrsAdaptiveCfg.
SrsPeriodAdaptive and
CellSrsAdaptiveCfg.UserSrsPeriod take effect only when the
SRSCfg.
FddSrsCfgMode parameter is set to DEFAULTMODE.
The CellSrsAdaptiveCfg.
SrsPeriodAdaptive parameter indicates whether to
enable or disable SRS period adaptation.
●  If this parameter is set to ON, the eNodeB adaptively adjusts the SRS period
for newly admitted UEs based on SRS loads. SRS resources may be normally
loaded, slightly congested, or heavily congested. A high SRS load results in a
long SRS period set for newly admitted UEs.
–   When the SRS resources are normally loaded, the eNodeB sets the SRS
period to 10 ms for newly admitted UEs. This reduces the interval for
updating SRS measurements, improving user experience. However, the
cell SRS capacity decreases.
–   When the SRS resources are slightly congested, the eNodeB sets the SRS
period to 20 ms for newly admitted UEs. This allows more UEs to access
the cell. However, user experience becomes less satisfactory.
–   When the SRS resources are heavily loaded, the eNodeB sets the SRS
period to 40 ms for newly admitted UEs. This allows more UEs to access
the cell and leads to a compromise between cell capacity and
performance.
–   The eNodeB does not adjust SRS periods for the admitted UEs that have
been allocated SRS resources.
–   The SRS period for a half-duplex eMTC UE must be longer than or equal
to 40 ms.
●  If this parameter is set to OFF, the eNodeB sets a fixed SRS period for newly
admitted UEs. The CellSrsAdaptiveCfg.
UserSrsPeriod parameter specifies the
fixed SRS period, which can be set to 5, 10, 20, 40, 80, 160, or 320 ms. For a
half-duplex eMTC UE, the SRS period can be set to 40, 80, 160, or 320 ms. If a
short fixed SRS period is configured, the maximum number of UEs using SRSs
in a cell may not reach the maximum allowed value. If a long fixed SRS
period is configured, the maximum number of such UEs in a cell increases but
the performance of features depending on SRS measurement deteriorates. If
the CellSrsAdaptiveCfg.
UserSrsPeriod parameter is set to a value greater
than 80 ms, uplink timing performance deteriorates and UE out-of-
synchronization occurs. In this situation, you are advised to reconfigure the
CellSrsAdaptiveCfg.
UserSrsPeriod parameter with parameters in the
TimeAlignmentTimer MO for the Uplink Timing Control feature.

7.1.3.3 UE-specific SRS Bandwidth
A UE sends SRSs within a bandwidth. The bandwidth is called a UE-specific SRS
bandwidth. UE-specific SRS bandwidths are obtained from cell-specific SRS
bandwidth configurations, corresponding to b = 0, 1, 2, and 3.
7.1.4 SRS and HARQ-ACK Processing
To prevent conflicts between SRSs and PUCCH HARQ-ACKs of a UE, during
conflicts, the eNodeB discards the SRSs, which results in the performance
deterioration of features depending on the SRS function, or truncates the HARQ-
ACKs and SRIs, which results in the deterioration of PUCCH demodulation
performance.
●  If the SRSCfg.
AnSrsSimuTrans parameter is set to BOOLEAN_TRUE:
–   The UE can simultaneously send an SRS and a PUCCH HARQ-ACK.
–   The UE can send truncated PUCCH HARQ-ACKs or SRIs.
–   The UE does not discard SRSs.
●  If the SRSCfg.
AnSrsSimuTrans parameter is set to BOOLEAN_FALSE:
–   The UE cannot simultaneously send an SRS and a PUCCH HARQ-ACK.
–   The UE can send only PUCCH HARQ-ACKs or SRIs.
–   The UE discards SRSs.
7.1.5 SRS Multiplexing
An SRS multiplexing mode determines how UEs transmit SRSs using time-
frequency resources.
## 7.1.5.1 FDM
The FDM mode allows UEs to transmit SRSs using different frequencies. FDM is
classified into localized frequency division multiplexing (LFDM) and distributed
frequency division multiplexing (DFDM).
## ●  LFDM
Different UEs use different RBs for continuously transmitting SRSs.
## ●  DFDM
Different UEs use discontinuous subcarriers for transmitting SRSs. If the
repetition factor (RPF) is 2, SRSs are transmitted only on even-numbered
subcarriers or odd-numbered subcarriers. SRSs have a comb transmission
interval, which is specified by the comb parameter. If the comb parameter is
set to 0, SRSs are transmitted on even-numbered subcarriers. If the comb
parameter is set to 1, SRSs are transmitted on odd-numbered subcarriers.
## 7.1.5.2 CDM
The CDM mode allows SRSs with the same subframe, bandwidth, and comb value
to occupy the same time-frequency position. Codewords use cyclic shift sequences
generated from the same Zadoff-Chu sequence. As defined in 3GPP, CDM supports
a maximum of eight cyclic shift sequences.

7.1.6 SRS Frequency Hopping
SRS frequency hopping enables a UE to transmit SRSs on a small frequency band
at one time and to transmit SRSs on another frequency band the next time. In this
way, the eNodeB achieves sounding on the entire channel bandwidth. SRS
frequency hopping implements channel quality measurements in the entire
channel bandwidth by using a small sounding bandwidth.
